Abstract

Content teams often need to decide which pages deserve review first when search performance suggests a possible opportunity. This capstone investigates whether observable Google Search Console (GSC) signals can support that prioritization.

Using daily content-performance data from May 2026, the analysis focuses on GSC impressions, clicks, and average search position. A transparent rule serves as the baseline, while Logistic Regression is tested as a simple probabilistic ranking model. The target defines a CTR review opportunity as content with at least 500 impressions, an average position between 1 and 20, and CTR below 0.5%.

The evaluation uses a client-grouped holdout split so that clients in the test set are never seen during training. On that split, the rule baseline reached F1 = 1.0000 — expected, since it is the target definition — while Logistic Regression reached F1 = 0.6584 with recall 0.9908 and precision 0.4930. The result is a ranked, reason-coded review queue meant strictly for human decision support.

01

Introduction

The content problem

Content teams cannot review every page with the same level of attention. A practical workflow needs a defensible way to decide what deserves investigation first.

The question behind this analysis is narrower and safer than "can ML solve SEO":

Research questionCan observable search-performance signals help a content team decide which items should be reviewed first?

This framing ties the modeling work directly to a real content decision. The output supports human prioritization — it does not automatically rewrite content or claim that a specific change will improve search performance.

03

Methodology

Target definition

A row is labeled a CTR review opportunity (1) when impressions ≥ 500, average position is between 1 and 20, and CTR < 0.5% (CTR = clicks / impressions × 100). Otherwise it is 0. The positive class is rare — about 1.6% of rows — so F1, not accuracy, is the metric that matters.

Baseline

The Week-4 rule applies that same threshold definition directly. It is a fair comparison point: identical signals, no information advantage either way.

Model

Logistic Regression, with StandardScaler preprocessing and class_weight="balanced" for the rare positive class. Features: gsc_impressions, gsc_clicks, gsc_avg_position — nothing else.

Validation design

Split grouped by client_hash_id (GroupShuffleSplit, 80/20, seed 42). Pages from the same client share traffic patterns, so a row-level split would leak client identity across train/test and inflate scores. The grouped split guarantees zero client overlap — 44 clients / 3,336,055 rows train, 11 clients / 900,965 rows test.

Leakage disclosed, not hiddenAll three model features are also the exact signals used to build the target label. This circular dependency is the single biggest caveat on every number in this paper — see Limitations.

The baseline's perfect score is expected, not impressive — it is the target definition. Logistic Regression trades that circularity for high recall at lower precision.

Naive vs. grouped split — an honesty check

Evaluating the same model on a naive row-level split gave an inflated F1 of 0.7224, versus 0.6584 on the client-grouped split — a real 0.064 drop once client leakage between train and test is removed. The grouped number is the one reported as the model's true performance.

Error analysis

On 900,965 test rows: 11,914 false positives, 108 false negatives. The model rarely misses a true opportunity (consistent with 0.99 recall) but flags many extra candidates (consistent with 0.49 precision) — a reviewer should expect roughly half of flagged items to be false alarms.

05

Limitations & honest framing

  • The target is derived from the same three GSC signals used as model features — a circular dependency that limits how strongly these scores can be interpreted.
  • The analysis is observational. It measures associations in search-performance data; it does not establish that a recommended change will cause a CTR improvement.
  • Results reflect the May 2026 data window and this grouped validation design. Performance may differ on future data, other clients, or other search environments.
  • The model produces prioritization signals, not editorial judgment — it has no notion of search intent, brand traffic, or business context.
Language used throughoutobserved · measured · directional · decision-support — never causal, never "predicts Google."
